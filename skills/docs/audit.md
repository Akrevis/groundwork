# audit（体检）：查文档的一致性（定期，由用户发起）

## 1. 跑机械的那一半

```bash
groundwork-audit
```

脚本在插件的 `bin/` 里，Claude Code 会把它加进 PATH。找不到这个命令 → 退回 `node bin/groundwork-audit`（只在当前目录就是 groundwork 仓库时可用），并报告插件的 `bin/` 不在 PATH 上——这本身就是一条发现。

它跑所有真正机械的检查，共 14 条：hook 能不能执行、skill 的种类清单、skill 的 frontmatter 会不会被静默作废、死链、`docs/` 下被 git 忽略或没提交的文件、ADR 编号重复或乱序、devlog 引用的 commit、章节引用、引用了 devlog 里已经不存在的 ADR、hook 已经采集却被手写的字段、留在 3.x 旧位置上的文档、放错地方的内容、对其他插件的依赖、「何时重审」清单。每条检查报告通过、有发现、**跳过并说明原因**，或者**出错**——抛异常的检查会说出来，不会假装通过。

`--json` 输出同样的结果，方便自己整理报告。

**不要手工重跑这些检查。** 在这里再写一份检查，就是第二份实现，迟早和第一份分叉；脚本是唯一的一份。

## 2. 发现只报告，不动手

**检测可以机械化，修复通常要判断。** 能查出来，不等于知道该怎么改。

例子：「`context.md` 引用的文件不存在」检测起来完全机械，但**修法不唯一**——删掉引用，还是补上本该存在的文件？脚本不知道，所以只报告。

体检**不直接修任何东西**。ADR 编号尤其不能重排：编号是永久 ID，commit message 里的引用改不了，一重排就全部指错。

输出里有两类是**清单，不是错误**——读，不要修：

- `skill-kinds`——列出每个 skill 是命令还是自动触发。哪个对，要读内容才知道，脚本只列
- `revisit-when`——列出 devlog 里每条「何时重审」。它触发了没有，机械判断不了

**三类发现是预期的，不是 bug：** 引用了某个包名的教训是记录，不是依赖；「代价见 ADR-011」这类是指针，不是放错的内容；查其他包名的那条检查会匹配到自己。关键词检查分不清「提到」和「依赖」——这类检查的上限就在这里，所以只报告不修。

## 3. 脚本做不到的那一半——真正要干活的地方

脚本只拿**文档比文档、文档比 git**，从不打开实现。下面这些归你，真正的漂移就在这里：

| 判断项 | 实际要做的 |
|---|---|
| **文档 vs 实现** | 读文档描述的代码，逐条核对 `requirements.md`、`architecture.md` 和 README 里的每个行为断言。描述一个没人实现过的机制，从文档内部看和真的一模一样 |
| **测试和发布还照得着做吗** | `testing.md` 的命令真跑一遍；`release.md` 的步骤和现在的仓库、脚本对得上吗，回滚那一块还走得通吗 |
| **图和文字** | `diagrams/` 里的图和 `requirements.md`、`architecture.md` 的文字说法一致吗；不一致的，按「AI 以文字为准」标出过期的图 |
| **描述还成立吗** | 项目定位、模块职责；ADR 的结论有没有被后来的做法推翻——推翻了，就按 devlog 规则删或改 |
| **结构性的坑** | 记了很久的坑还在不在、还过不过得了三道检查。机械判断不了，有疑问的提出来 |
| **待办和话题** | `docs/3-development/tasks/` 里的待办还活着吗（注入里的「N 天没动」是线索）；`plans/` 里有没有话题已经默默定了，却没转成待办、没写进对应的文档、也没删 |
| **归档背景 vs 代码** | 每份归档背景写的前提和取舍，和它「涉及的文件」现在的代码还对不对得上；它做出来的东西还在不在 |
| **roadmap 阶段** | 阶段划分还准不准 |

这一节的结论**必须标成判断而非事实**，需要用户核实，绝不自动修。

## 输出四段

1. **需要你决定**——发现了问题，但修法不唯一，列出选项
2. **信号**——不是错误，是架构健康度的指标：`context.md` 在长、坑在变多、模块表在长、待办堆积或长期不动
3. **判断项的结论**——第 3 步的发现，标明是判断
4. **这次没查的**

第 4 段最重要：体检漏掉的远比查到的多。没有它，全绿会给人**虚假的信心**——**一个不说明自己查了什么的检查，比不查更危险。**

## 不自动触发

不让 hook 在漂移超过阈值时提示跑体检：那是工具拿自己来提醒用户，正是这个包拒绝制造的噪音；而漏跑一次体检的代价，只是问题积累一阵，不会立刻坏掉。想跑时再跑。
