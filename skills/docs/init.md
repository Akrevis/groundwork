# 建档：给项目建立文档骨架（每个项目一次）

## 1. 预检

`docs/context.md` **已经存在** → 停下，告诉用户这个项目已经建过档，问他是要 `收尾` 更新它，还是真的要重建。**绝不覆盖**——那个文件里的每一条都是问来的，覆盖等于重新问一遍。

**先看项目里已经有什么。** 列出 `docs/` 下和仓库根目录的 markdown 文件，排除 `README*`、`LICENSE*`、`CHANGELOG*`、`CONTRIBUTING*`。有发现 → **逐个停下问**它该归到哪：

| 现有文件 | 可以去哪 |
|---|---|
| 设计文档 | 变成 `design.md`——哪些属于核心区、哪些属于阶段区 |
| 决策记录 | 变成 `devlog.md`，只留现在有效的 |
| 待办或待定清单 | 每一条变成 `plans/` 话题或 `tasks/` 待办 |
| 其他 | 留在原处，不进这套布局 |

**绝不自己移动、改名或改写。** 它们装着用户的工作，猜错了就得手工回退。写代码之前写的设计文档是设计稿，按设计稿映射进 `design.md`，不要把它说成架构快照。

## 2. 能机械读到的先读，不问

列出顶层目录，用来起模块表。滤掉明显不是模块的：`node_modules`、`.git`、`dist`、`build`、`target`、`venv`、`__pycache__`、`.venv`、`vendor`。

**技术栈、分支、未提交改动、最近提交、待办列表一律不问、不写**——hook 每次会话都会采集，写进文件只会漂移。目录是例外：hook 不列目录，模块表就是目录的落脚处。

## 3. 问四件事（不猜，不从 README 推断）

**为什么不猜**：猜错的内容会被**强制注入每一次会话**，AI 还会把它当成权威。这个代价远大于多问几句。

| 问 | 说明 | 能空着吗 |
|---|---|---|
| **这个项目是什么** | 一句话：给谁用，解决什么 | 不能，这是最核心的 |
| **不做什么** | 明确不做的，防止 AI 自己扩范围 | 可以先空，但强烈建议填 |
| **每个目录负责什么** | 列出第 2 步的目录，请用户每个给一句 | 还没有代码 → 整节省略 |
| **有没有已知的坑** | **只收永久、反复撞、任何 clone 的人都会撞的。** 能修的修掉；只在本机撞的放用户级记忆 | 新项目一般没有 → 整节省略 |

用户说主旨还没想清楚，也照样先写一句临时的，第 4 步再把第 0 层列为开局话题。

## 4. 定开局的话题和草案

决策顺序（见 `decision-order` skill）的第 0 层由用户定，第 1～6 层由 AI 按阶段起草。建档时把**还没定的**记下来：

| 还没定的 | 记成 | 什么时候预置 |
|---|---|---|
| 第 0 层主旨 | `plans/0-主旨.md` | 用户说主旨还没想清楚 |
| 第 1～6 层：边界、形态、模块、技术栈、目录与接口、开工顺序 | 一份当前阶段的草案 `plans/1-<阶段>草案.md` | 其中有任何一层还没定 |

- **新项目**（还没有代码）：第 1～6 层一般都没定，预置 `plans/1-第一版草案.md`；第 0 层按上表的条件
- **已有代码的项目**：列出第 1～6 层，标出看得出已经定了的（有 `package.json`、`go.mod` 之类，技术栈就定了；目录已经摆好，目录就定了），**问用户项目现在在哪个阶段、哪些层还开着**。有开着的，就建这个阶段的草案；都定了，不建
- 第 7 层细节不预置，它们会在讨论里自己冒出来

开局话题按 SKILL.md 的话题模板写：来源写「项目开局，这一层还没定」；要解决什么写这一层要定的内容（取 `decision-order` 对应层的「定什么」）；讨论记录写「无」。

草案按 SKILL.md 的阶段草案模板写，**建档时不起草**：来源写「项目开局」，加上用户在第 3 步说过的想要；草案块写「还没起草」并列出还没定的层；讨论记录写「无」。起草是一场讨论——先听用户想要什么，属于 `decision-order` 那五类的结论要先查——塞进建档只会草草了事。

## 5. 生成

写 `docs/context.md`（按 SKILL.md 的模板）和第 4 步的开局话题、草案。**不建别的文件和目录**——`tasks/`、`archive/` 等到第一个文件出现时才建。

## 6. 提交和报告

提交（见 SKILL.md「提交」），然后报告：

- 建了哪些文件，commit 是哪个
- **注入怎么生效**：装好 groundwork 插件就行，不用任何配置
- 下次会话开场会出现 `<groundwork-context>`，「待讨论」那一行会显示最靠前的开局话题或草案
- **下一步**：建了草案的，接下来的讨论从起草开始——跟 AI 说说你想要它做什么、怎么用、在哪用，它按 `decision-order` 出草案
