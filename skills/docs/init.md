# 建档：给项目建立文档骨架（每个项目一次）

## 1. 预检

`docs/context.md` **已经存在** → 停下，告诉用户这个项目已经建过档，问他是要 `收尾` 更新它，还是真的要重建。**绝不覆盖**——那个文件里的每一条都是问来的，覆盖等于重新问一遍。

**先看项目里已经有什么。** 列出 `docs/` 下和仓库根目录的 markdown 文件，排除 `README*`、`LICENSE*`、`CHANGELOG*`、`CONTRIBUTING*`。有发现 → **逐个停下问**它该归到哪：

| 现有文件 | 可以去哪 |
|---|---|
| 设计文档 | 变成 `design.md`——哪些属于核心区、哪些属于阶段区 |
| 决策记录 | 变成 `devlog.md`，只留现在有效的 |
| 待办或待定清单 | 每一条变成 `plans/` 话题或 `tasks/` 待办 |
| 其他 | 留在原处，不进这套布局 |

**绝不自己移动、改名或改写。** 它们装着用户的工作，猜错了就得手工回退。写代码之前写的设计文档是设计稿，按设计稿映射进 `design.md`，不要把它说成架构快照。

## 2. 能机械读到的先读，不问

列出顶层目录，用来起模块表。滤掉明显不是模块的：`node_modules`、`.git`、`dist`、`build`、`target`、`venv`、`__pycache__`、`.venv`、`vendor`。

**技术栈、分支、未提交改动、最近提交、待办列表一律不问、不写**——hook 每次会话都会采集，写进文件只会漂移。目录是例外：hook 不列目录，模块表就是目录的落脚处。

## 3. 问四件事（不猜，不从 README 推断）

**为什么不猜**：猜错的内容会被**强制注入每一次会话**，AI 还会把它当成权威。这个代价远大于多问几句。

| 问 | 说明 | 能空着吗 |
|---|---|---|
| **这个项目是什么** | 一句话：给谁用，解决什么 | 不能，这是最核心的 |
| **不做什么** | 明确不做的，防止 AI 自己扩范围 | 可以先空，但强烈建议填 |
| **每个目录负责什么** | 列出第 2 步的目录，请用户每个给一句 | 还没有代码 → 整节省略 |
| **有没有已知的坑** | **只收永久、反复撞、任何 clone 的人都会撞的。** 能修的修掉；只在本机撞的放用户级记忆 | 新项目一般没有 → 整节省略 |

用户说主旨还没想清楚，也照样先写一句临时的，第 4 步再把第 0 层列为开局话题。

## 4. 定开局话题

决策顺序的前几层（见 `decision-order` skill）是每个项目都要先定的。建档时把**还没定的**各记成一个话题：

| 层 | 话题文件 | 什么时候预置 |
|---|---|---|
| 0 主旨 | `plans/0-主旨.md` | 用户说主旨还没想清楚 |
| 1 边界 | `plans/1-边界.md` | 「不做什么」空着 |
| 2 形态 | `plans/2-形态.md` | 还没定做成什么、跑在哪 |
| 3 模块 | `plans/3-模块.md` | 还没定顶层分几块 |
| 4 技术栈 | `plans/4-技术栈.md` | 还没定语言、框架、存储 |
| 5 目录与接口 | `plans/5-目录与接口.md` | 还没定目录怎么摆、模块之间传什么 |
| 6 开工顺序 | `plans/6-开工顺序.md` | 还没定先做哪块 |

- **新项目**（还没有代码）：第 2～6 层一般都没定，全部预置；第 0、1 层按上表的条件
- **已有代码的项目**：列出第 2～6 层，标出看得出已经定了的（有 `package.json`、`go.mod` 之类，技术栈就定了；目录已经摆好，目录就定了），**问用户哪些还开着**，只预置开着的
- 第 7 层细节不预置，它们会在讨论里自己冒出来

每份开局话题按 SKILL.md 的话题模板写：来源写「项目开局，这一层还没定」；要解决什么写这一层要定的内容（取 `decision-order` 对应层的「定什么」，能按项目具体化就具体化）；讨论记录写「无」。

## 5. 生成

写 `docs/context.md`（按 SKILL.md 的模板）和第 4 步的开局话题。**不建别的文件和目录**——`tasks/`、`archive/` 等到第一个文件出现时才建。

## 6. 提交和报告

提交（见 SKILL.md「提交」），然后报告：

- 建了哪些文件，commit 是哪个
- **注入怎么生效**：装好 groundwork 插件就行，不用任何配置
- 下次会话开场会出现 `<groundwork-context>`，「待讨论」那一行会显示最靠前的开局话题
